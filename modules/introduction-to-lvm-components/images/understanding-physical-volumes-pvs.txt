In the Logical Volume Manager, or LVM architecture, the Physical Volume, or PV, acts as the fundamental building block. Before LVM can manage storage, it must identify and label the underlying hardware to treat it as a flexible pool of data.

Let’s take a closer look at what a Physical Volume actually is. A Physical Volume is a storage device, or a partition on a storage device, that has been initialized for use by LVM. By converting a raw block device into a PV, you add an LVM metadata header to the disk. This header describes the device as part of the LVM subsystem, which allows the kernel and LVM tools to manage the storage beyond the limitations of standard disk partitions.

There are three key characteristics of Physical Volumes to keep in mind. First, they provide an abstraction layer, hiding the physical geometry of the hard drive or SAN LUN from the file system. Second, they require initialization; before a device can be used as a PV, it must be initialized using the "pvcreate" command. This process writes an LVM label to the start of the device. Finally, they offer flexibility. Once a device is a PV, it can be assigned to a Volume Group. Because LVM works with the space provided by the PV, you can easily resize, extend, or remove disks from your storage topology without the need to unmount file systems or repartition the hardware.

In a typical Red Hat Enterprise Linux environment, such as those used for high-performance workloads like SAP HANA, the storage hierarchy is organized in a specific stack. It begins with the raw hardware device, for example, slash dev slash sdb. That device is then transformed into a Physical Volume using the "pvcreate" command. Next, one or more Physical Volumes are collected into a Volume Group, which acts as a single storage pool. Finally, a Logical Volume is carved out of that Volume Group, formatted with a file system like XFS, and mounted to the directory tree.

While automation tools like the RHEL system roles storage role handle these tasks in production, understanding the underlying commands is critical for troubleshooting and manual configuration.

To initialize a block device for LVM use, run the "pvcreate" command followed by the device name, such as "pvcreate /dev/sdb". You will see a confirmation message indicating the physical volume was successfully created.

To inspect existing Physical Volumes on your system and verify their status, metadata, and available capacity, use the "pvs" or "pvdisplay" commands. When you run "pvs", the system displays a summary table. This shows you the device name, the Volume Group it belongs to, the total size of the physical device available to LVM, and the amount of unallocated space remaining on that specific volume.

Consider the practical implications for SAP HANA. In scenarios where performance-critical volumes like slash-hana-data and slash-hana-log are required, LVM allows you to aggregate multiple fast NVMe or SSD drives into a single Volume Group. By creating multiple Physical Volumes from these high-speed devices, you can create large, performant Logical Volumes that meet the specific capacity requirements outlined in your SAP sizing documentation.
