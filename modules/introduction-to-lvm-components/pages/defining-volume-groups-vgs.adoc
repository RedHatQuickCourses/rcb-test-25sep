#  Defining Volume Groups (VGs)

= Defining Volume Groups (VGs)

In the Logical Volume Manager (LVM) architecture, a **Volume Group (VG)** acts as the central storage pool. It is the abstraction layer that collects one or more Physical Volumes (PVs) and combines them into a single, unified storage entity.

== What is a Volume Group?

A Volume Group is the container that sits between the physical storage hardware and the logical volumes (LVs) used by the operating system. By grouping multiple physical disks or partitions together, LVM provides a flexible way to manage space that is no longer restricted by the physical size of an individual disk.

Key characteristics of VGs include:
* **Storage Pooling:** Multiple PVs of varying sizes can be joined into one VG.
* **Elasticity:** You can expand a VG at any time by adding new Physical Volumes to it without needing to migrate existing data.
* **Abstracted Space:** Once the VG is created, space is carved out of the pool to create Logical Volumes.

== Creating a Volume Group

To create a Volume Group, you use the `vgcreate` command. This command takes a name for the new VG and a list of Physical Volumes that will contribute their storage to the pool.

[source,bash]
----
# Syntax: vgcreate [vg_name] [pv_path1] [pv_path2]...
[root@localhost ~]# vgcreate vg_data /dev/sdb1 /dev/sdc1
----

In this example, the two partitions, `/dev/sdb1` and `/dev/sdc1`, are initialized as PVs and combined into a single Volume Group named `vg_data`.

== Physical Extents (PEs)

When a VG is created, LVM divides the total available space into fixed-size chunks called **Physical Extents (PEs)**. 
* All PEs within a single Volume Group are the same size (the default is usually 4MB).
* When you create a Logical Volume, LVM allocates these extents to the LV.
* Because the VG is essentially a collection of PEs, LVM can spread a single Logical Volume across multiple physical disks seamlessly.

== Inspecting Volume Groups

To verify the status and capacity of your Volume Groups, use the `vgs` and `vgdisplay` commands.

* **`vgs`:** Provides a concise, one-line summary of all VGs on the system.
+
[source,bash]
----
[root@localhost ~]# vgs
  VG      #PV #LV #SN Attr   VSize   VFree
  rhel      1   2   0 wz--n- <11.00g    0 
  vg_data   2   0   0 wz--n-  19.99g 19.99g
----

* **`vgdisplay`:** Provides detailed information about a specific VG, including the PE size, the number of free extents, and the physical volumes associated with the group.
+
[source,bash]
----
[root@localhost ~]# vgdisplay vg_data
  --- Volume group ---
  VG Name               vg_data
  System ID             
  Format                lvm2
  Metadata Areas        2
  VG Size               19.99 GiB
  PE Size               4.00 MiB
  Total PE              5118
  Alloc PE / Size       0 / 0 
  Free  PE / Size       5118 / 19.99 GiB
----

== Extending a Volume Group

One of the primary benefits of using LVM is the ability to grow the VG size online. If you add a new physical disk to your server, you can add it to an existing VG using the `vgextend` command:

[source,bash]
----
[root@localhost ~]# vgextend vg_data /dev/sdd1
  Volume group "vg_data" successfully extended
----

This immediately increases the `VFree` (Free Space) of the `vg_data` group, allowing you to create or resize Logical Volumes without unmounting or restarting the system.
